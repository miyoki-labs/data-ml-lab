# AI の使い方の記録

目的は、**同じ成果を、少ない往復と少ない文脈で出せるようになる**こと。業務で AI を使うときの「速さ」と「費用」は、ほぼこの2つで決まる。

## 記録のしかた

課題が1つ終わるたびに1行足す。数えるのは、道具が無くても数えられるものだけにする。

- **往復**＝AI に送ったメッセージの数
- **貼った行数**＝ログ・コード・エラーを貼った行数の合計（おおよそでよい）
- **所要**＝課題の開始から判定が通るまでの分数
- **次は**＝次に同じことをするなら、何を変えるか（1つだけ）

| 日付 | 課題 | 往復 | 貼った行数 | 所要（分） | AI に聞かずに済んだこと | 次は |
|---|---|---|---|---|---|---|
| | | | | | | |

## フェーズごとに足す型

| フェーズ | 身につける型 | なぜ効くか |
|---|---|---|
| Phase0 | `--help`／`man` を先に見る・貼るのは該当行だけ・1課題1会話 | 渡す文脈が小さいほど、読み込み量も答えのぶれも減る |
| Phase1 | SQL を聞くときは**表の定義だけ**渡し、データ本体は渡さない | 量が減るうえ、顧客データを外へ出さない習慣になる |
| Phase2 | 設定ファイルは**差分だけ**渡す | 全文より短く、どこを変えたかが AI にも自分にも明確になる |
| Phase3 | 毎回同じ処理は**スクリプトにして AI を呼ばない**。AI は判断が要る部分だけ | 1回あたりの費用がほぼ0になり、結果も毎回同じになる |
| Phase4 | API で使うときは、モデルの使い分け・キャッシュ・まとめて処理する方式を比べ、**1回あたりの費用を見積もる** | 小規模事業者への提案で「月いくらかかるか」を答えられる |
| Phase5 | ここまでの記録から「AI 運用費の見積もり表」を1枚にまとめる | 提案書にそのまま載せられる |
