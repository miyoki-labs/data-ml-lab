# AI の使い方の記録

目的は、**同じ成果を、少ない往復と少ない文脈で出せるようになる**こと。この記録では、その2つ（往復の数と、渡した文脈の量）が減っていくかを測る。

## 記録のしかた

課題が1つ終わるたびに1行足す。数えるのは、道具が無くても数えられるものだけにする。

- **往復**＝その課題のあいだに AI に送ったメッセージの数。質問だけでなく、「できてる？」の確認や「動いた」の報告も1回と数える（送るたびに手間と費用が増えるため）。記憶ではなく会話の履歴で数える
- **貼った行数**＝ログ・コード・エラーを貼った行数の合計（おおよそでよい。画面の画像は、写っているうち読んでほしい行の数）
- **所要**＝課題の開始から判定が通るまでの分数
- **AI に聞かずに済んだこと**＝`--help`・`man`・自分の推測で解決できたこと。無ければ「なし」（最初は「なし」が普通。減っていくかを見る）
- **次は**＝次に同じような作業をするとき、**AI の使い方で**1つ変えるなら何か（例：エラーは該当の1行だけ貼る）。次にやる作業のことではない。思いつかなければ空欄

| 日付 | 課題 | 往復 | 貼った行数 | 所要（分） | AI に聞かずに済んだこと | 次は |
|---|---|---|---|---|---|---|
| 2026-10-01 | 準備＋課題1 | 5 | 約3 | 30 | なし（ほぼ全部聞いた） | |

- 10/1 の往復は会話の履歴で数えた。記憶での見立ては3〜4だった（記憶は少なめに出た）。

## フェーズごとに足す型

| フェーズ | 身につける型 | なぜ効くか |
|---|---|---|
| Phase0 | `--help`／`man` を先に見る・貼るのは該当行だけ・1課題1会話 | 渡す文脈が小さいほど、読み込み量も答えのぶれも減る |
| Phase1 | SQL を聞くときは**表の定義だけ**渡し、データ本体は渡さない | 量が減るうえ、顧客データを外へ出さない習慣になる |
| Phase2 | 設定ファイルは**差分だけ**渡す | 全文より短く、どこを変えたかが AI にも自分にも明確になる |
| Phase3 | 毎回同じ処理は**スクリプトにして AI を呼ばない**。AI は判断が要る部分だけ | AI の呼び出しを省けた処理では、その分の費用と答えのばらつきを抑えられる |
| Phase4 | API で使うときは、モデルの使い分け・キャッシュ・まとめて処理する方式を比べ、**1回あたりの費用を見積もる** | 小規模事業者への提案で「月いくらかかるか」を答えられる |
| Phase5 | ここまでの記録から「AI 運用費の見積もり表」を1枚にまとめる | 提案書にそのまま載せられる |
