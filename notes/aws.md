## 用語・サービス

| サービス | 一言でいうと |
|---|---|
| Amazon Bedrock | いろいろな会社の基盤モデル（※大量のデータで学習済みの汎用 AI。Claude など）を API で使える |
| Amazon SageMaker AI | 機械学習のモデルを自分で作る・学習させる・動かす |
| Amazon Textract | 画像や PDF から文字と表を取り出す（領収書・請求書の読み取り） |
| Amazon Transcribe | 音声 → 文字 |
| Amazon Comprehend | 文章の意味を読む（感情・キーワード・個人情報） |
| Amazon Kendra | 社内文書から、質問に合う箇所を探して返す。⚠️ 2026-07-30 で新規の受付を終了（既存の利用者だけ）。新しく RAG を作るなら Bedrock の Knowledge Bases（※探して答える仕組みを丸ごと用意する機能） |
| Amazon Macie | S3（※AWS のファイル置き場）の中の個人情報を見つけて知らせる＝「守る」側 |

| SageMaker Model Monitor | 動いているモデルの質が落ちていないかを見張る |
| Amazon Augmented AI（A2I） | AI の判断を人が確認する流れを入れる |

### 機械学習の基礎（Domain 1 Review）

| 用語 | 一言でいうと |
|---|---|
| 特徴量 | モデルに渡す入力の項目。表なら列、画像なら画素 |
| トレーニング（学習）／推論 | 答えの分かっているデータでパラメータを調整する ／ 学習済みのモデルで新しいデータを予測する |
| パラメータ | 学習中に調整される値（y＝ax＋b の a と b） |
| 構造化・半構造化・非構造化データ | 表（CSV・RDS）／ キーと値（JSON・DynamoDB）／ 表にできない（画像・文章。S3 に置く） |
| 過学習／過小適合 | 学習データ ○・新しいデータ × ／ どちらも × |
| ロジスティック回帰 | 名前は「回帰」だが、やることは分類（確率を出して、しきい値で分ける） |
| 決定論的／確率論的 | 出力の性質：同じ入力なら必ず同じ答え ／ 答えにばらつきや確からしさの幅がある。⚠️ 「ルールのプログラム＝決定論的、機械学習＝確率論的」とは言い切れない（学習済みのモデルも、同じ入力・同じ設定なら同じ答えを返すことがある。機械学習の答えは「確率」として出ることが多い、が正確） |

## 使い道（受託＝小規模事業者の AI 業務自動化に結び付けると）

- Textract：紙の領収書や請求書を、表計算に手で打ち直している作業をなくす
- Transcribe：会議や電話を文字にして、議事録を作る（要約まで行うなら Bedrock と組み合わせる）
- Bedrock の Knowledge Bases：その会社のマニュアルから探して答える RAG（※社内文書を探してから、それを元に AI が答える仕組み）。Kendra は新規の受付を終えたので、新しく作るならこちら
- Macie：顧客名簿やクレームの記録を S3 に置くときに、個人情報が見える場所に置かれていないかを見張る
- Clarify：審査などを AI に手伝わせるとき、特定の層に不利になっていないかを、お客さんに説明できる形で確かめる
- **ルールで書けることは、AI を使わない**（ルールで書いたプログラムのほうが安くて、答えが毎回同じ）。AI は判断が要る部分だけ。記録表の Phase3 の型と同じ考え方
