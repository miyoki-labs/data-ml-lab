## 用語・コマンド

### ファイルと場所

| コマンド | 元の英語 | 一言でいうと |
|---|---|---|
| `pwd` | print working directory | 今いる場所を表示する |
| `cd` | change directory | 場所を移る（`cd ..`＝1つ上、`cd ~`＝ホーム） |
| `ls -l` | list ＋ long | 一覧を詳しく（権限・所有者・サイズ・日時） |
| `ls -a` | list ＋ all | `.` で始まる隠しファイルも見せる |
| `mkdir -p` | make directory | フォルダを作る（`-p`＝途中のフォルダもまとめて） |
| `touch` | 触る | 空のファイルを作る（あれば日時だけ更新） |
| `cp` | copy | 複製する |
| `rm` | remove | 消す。**ゴミ箱に入らない** |
| `cat` | concatenate | 中身を全部表示する |
| `less` | − | 1画面ずつ読む（`q` で抜ける） |
| `nano` | − | ターミナルの中のメモ帳（Ctrl+O 保存・Ctrl+X 閉じる） |

- **絶対パス**＝どこから見ても同じ住所（`/home/miyoki/lab/phase0/x`）。**相対パス**＝今いる場所から見た道順（`./x`・`../x`）
- `~`＝自分のホーム。`./`＝今いるフォルダ。`..`＝1つ上

### 権限

`ls -l` の左端 `-rw-r--r--` の読み方：

| 位置 | 意味 |
|---|---|
| 1文字目 | `-`＝ファイル、`d`＝フォルダ |
| 次の3文字 | 所有者の 読む（r）・書く（w）・実行（x） |
| 次の3文字 | グループ |
| 最後の3文字 | その他の人 |

- 新しいファイルに `x` が最初から付かないのは、うっかり実行されないための安全側の既定
- `chmod +x file`＝実行権限を付ける
- 実行できるかは**名前（`.sh`）ではなく `x` の権限**で決まる（Windows は拡張子で決まるのと違う）

### 出力の行き先

| 記号 | 意味 |
|---|---|
| `>` | 出力をファイルへ（**上書き**） |
| `>>` | 出力をファイルの**末尾に追記** |
| `\|` | 出力を次のコマンドの入力へ（パイプ） |
| `A ; B` | A が終わったら B（A が失敗しても B は動く） |
| `A && B` | A が**成功したら** B |

### テキスト処理（課題2）

| コマンド | 一言でいうと |
|---|---|
| `grep 語 file` | その語を含む行だけ残す |
| `sort` | 並べ替える（`-n`＝数字として、`-r`＝逆順） |
| `uniq -c` | **隣り合う**同じ行を1行にまとめ、回数を付ける |
| `head -5` | 先頭から5行だけ |
| `tr -cs 'A-Za-z' '\n'` | 英字以外を改行に変え、続いたら1つにまとめる＝1行に1単語 |
| `LC_ALL=C コマンド` | 言語設定による並び順の違いを無くす。**直後の1コマンドにしか効かない** |

### プロセスとサービス（課題3）

| コマンド | 一言でいうと |
|---|---|
| `ps aux` | 今動いているプログラム（プロセス）の一覧。`PID`＝番号、`START`＝起動日時、`COMMAND`＝何か |
| `systemctl status docker` | サービスの状態。`Loaded:` 行と `Active:` 行を見る |
| `systemctl is-active docker` | **今**動いているか（`active`） |
| `systemctl is-enabled docker` | **起動したら**自動で動くか（`enabled`） |
| `journalctl -u docker` | そのサービスのログ（`--no-pager`＝`less` のようなページャーを使わずに出す、`-o cat`＝本文だけ。どこまでの範囲が出るかは `--since` などの指定とログの保存状況による） |

- PID 1 の `/sbin/init`＝Ubuntu の中で最初に起動した親玉（systemd）。`systemctl` はこれに聞いている

### 定期実行（課題4）

- `#!/bin/bash`（シバン）＝「このファイルは bash で実行して」という宣言
- `crontab -e`＝予定表を編集、`crontab -l`＝表示
- 書き方＝`分 時 日 月 曜日 実行するもの`。`*/5 * * * *`＝5分ごと
- **`crontab -r` は予定表を全部消す**（`-e` と1文字違い）。止めるときは `-e` で1行だけ消す

## つまずいたところ

| 日付 | 最初の理解 | 正しい理解 |
|---|---|---|
| 10/1 | `echo 'echo hello' > hello.sh` で何も表示されないのはなぜ？ | `>` が出力をファイルへ回したから。`cat` で見ると中身が残っている |
| 10/1 | `./hello.sh` で `echo` が出ずに `hello` だけになるのはなぜ？ | ファイルの中の `echo hello` は**文字ではなく命令として実行される**。命令そのものは表示されない（「『こんにちは』と言え」のメモを渡された人は「こんにちは」とだけ言う） |
| 10/2 | `uniq` だけで重複がまとまると思った | `uniq` は**すぐ上の1行としか比べない**。だから先に `sort` で同じものを隣に並べる（前の1行だけ覚えれば済むので、巨大なログでも軽く動く） |
| 10/2 | `uniq -c`＝重複を消す | **まとめて回数を付ける**。`-c` が無ければ消すだけ |
| 10/5 | `systemctl status` に `Loaded:`・`Active:` が見当たらない | 2行目と3行目にある。画面の幅で右が切れていた（`e>`＝`enabled`）。切れた部分は `is-enabled` などで1つずつ聞く |

## 使い道

- **ログの調査**：`journalctl … | grep … | sort | uniq -c | sort -rn | head`＝何が何回起きたかを数える（12月からの毎日の収集で、失敗の回数を数える）
- **止まったときの確認**：`systemctl is-active`／`is-enabled`／`journalctl -u` の3つで「今動いているか」「再起動しても動くか」「何が起きたか」が分かる
- **自動実行**：スクリプトは**絶対パス**で書き、**動いた証拠をファイルに残す**（cron は失敗しても何も言わないし、自分の居場所を知らずに動く）
- **AI と作業するとき**：AI が打ったコマンドを読めることが、AI に安全に作業させる条件になる
